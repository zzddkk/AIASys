### 修复模型实际返回的思考内容被抑制、以及思考泄露进正文

#### 问题描述

- 现象一：部分模型明明返回了思考内容，界面却看不到——「关闭思考」的开关被错误地
  接到了渲染层，导致「开关关了就不显示」，而不是「模型没吐就不显示」。
- 现象二：`step-` 系列等强制思考模型无法关闭思考，界面却仍显示一个「关闭」控件，
  点了没用。
- 现象三：部分模型把推理直接写在正文里（`<think>` 包裹），未剥离就渲染，思考内容
  泄露进正文。
- 原因：思考开关与思考渲染耦合；强制思考模型没有能力标识；`reasoning_in_content_tag`
  配置链路断裂——字段声明了但序列化没转发，运行时永远读不到值，`<think>` 剥离功能
  从未生效过一次。

#### 改动内容

- 删除 `suppress_reasoning_content` 及全部门控逻辑：渲染层只认模型实际吐出的事件，
  不认开关状态。
- 强制思考模型归一化为 `always_thinking` 能力标识，UI 显示「常开」徽章，
  不再渲染假的关闭控件。
- 后端剥离正文内 `<think>` 标签；补齐 `reasoning_in_content_tag` 从用户配置到运行时
  的完整链路，并加三个探针防复发。

- `apps/backend/app/services/agent/runtime_backends/aiasys/`: 思考事件与标签剥离

### CI 从形同虚设改为真门禁

#### 问题描述

- 现象：CI 看起来有一堆检查，实际大量步骤永远通过——`ruff check` 完全不在 CI 里
  （只有 `format --check`），`pylint` 是 `--exit-zero`，`mypy` 是 `|| true`；
  两个 workflow 语法本身就是坏的；9 个 job 没有超时上限。
- 原因：这些步骤被写成「不会失败」的形式，等于用绿色掩盖问题。首次把 `ruff check`
  接进来实测有 40 个 error（其中 8 个 F821 是真实缺陷）。

#### 改动内容

- `ruff check` 纳入 CI 并清零；`ruff format --check` 范围扩到 `tests/` 与仓库根 `scripts/`。
- `pylint` 与 `mypy` 改**棘轮**（分数不得低于基线、错误数不得超过基线），不再永远通过。
- 修两个语法坏掉的 workflow，补 9 个 job 的超时上限，新增 YAML 校验门。
- 新增**文档路径检查门**：文档里引用的源码路径必须真实存在（首次实测在 318 份文档里
  查出 38 个失效引用）。
- Windows 纳入 CI 矩阵（观察期内不阻塞合并），并修 Windows 特有问题：控制台编码、
  glob 不展开、字体缺失、vendor 二进制缺失。

#### 文件变更

- `.github/workflows/ci.yml`、`ci-desktop.yml`
- `scripts/dev/check_doc_paths.py`

### 发布脚本修正：版本号漏同步与 dry-run 副作用

#### 问题描述

- 现象：仓库根 `package.json` 的版本号停在 `0.4.33`，而 web / desktop / backend 都是
  `0.4.34`——同一个仓库里读到两个不同的「当前版本」。
- 原因：`release.sh` 的版本文件列表在 update / `git diff` / `git add` 三处各列一遍，
  根 `package.json` 从未被列入，漏改不报错。另外 `--dry-run` 会真的改文件、只提示
  「请手动 reset」，忘了就留下脏工作区，而下次发布的前置检查恰好要求工作区干净。

#### 改动内容

- 版本文件收敛为单一 `VERSION_FILES` 数组，三处复用，根 `package.json` 纳入同步。
- `--dry-run` 改为零副作用：跑完自动还原版本号文件。

#### 文件变更

- `scripts/dev/release.sh`
